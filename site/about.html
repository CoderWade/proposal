关于链上提案库

把散落在 GitHub 仓库里的 EIP、ERC、BIP 提案整理成一份能检索、能分类、能看影响面的中文索引。 所有内容来自官方仓库的原始 Markdown / MediaWiki 文件，站点是纯静态页面，不依赖任何后端服务。

数据从哪来

  • EIP：ethereum/EIPs 仓库 EIPS/eip-*.md
  • ERC：ethereum/ERCs 仓库 ERCS/erc-*.md（应用层标准已从 EIP 仓库迁出，本站合并展示）
  • BIP：bitcoin/bips 仓库 bip-*.mediawiki 与 bip-*.md

抓取走 codeload.github.com 的仓库压缩包，一次拉全量文件，比逐个调用 API 更稳且不受接口限流影响； 同时用 GitHub API 记录每个仓库最新的 commit 作为数据版本锚点。

多久更新一次

GitHub Actions 每 6 小时触发一次 scripts/pipeline.py：下载官方仓库 → 解析元数据 → 翻译 → 生成静态页面 → 提交并发布。 也可以手动在 Actions 页面点 Run workflow 立即同步。

中文是怎么来的

标题、描述与摘要/动机/设计理由/向后兼容性/安全考量五个章节通过 Google Translate 公共接口做机器翻译， 结果按源文本哈希缓存在 data/cache/translations.json。缓存命中时不会重复请求，因此定时任务的开销主要集中在新提案上。 详情页提供「中文 / EN」切换，可随时对照原文。

机器翻译只适合快速理解。涉及 gas 计算、字节布局、密码学参数、共识规则的部分，请以详情页右侧的「查看官方原文」链接为准。

影响面评估的口径

「影响 高 / 中 / 低」是本站基于可计算信号给出的启发式判断，不是官方评级。打分因子包括：

  • 状态是否已定稿或已部署（Final / Deployed / Living / Complete）
  • 是否触及核心协议或共识层（Core、Consensus soft/hard fork）
  • 被其他提案引用的次数（依赖图中的入度）
  • 提案类型（Standards Track / Specification 权重更高）

站内同时展示「依赖的前置提案」与「被引用次数」，你可以直接沿着依赖图判断一个提案在协议演进中的位置， 而不必只依赖这个评级。

主题标签怎么打

标签是从标题、描述、摘要与动机里做关键词匹配得到的，覆盖账户抽象、交易格式、费用市场、质押与共识、扩容与 L2、 密码学与签名、P2P 网络、钱包与密钥、代币标准、DeFi、隐私、跨链、合约接口、安全、治理、比特币脚本、地址格式等 17 类。 匹配是透明的规则式判断，可能不完全准确，用于快速聚类而非权威分类。

版权与免责

EIP/ERC 文档采用 CC0 1.0；BIP 文档采用各自在文件头声明的许可证（常见为 BSD-2-Clause、BSD-3-Clause、CC0）。 本站仅做索引、翻译与展示，原文版权归各提案作者所有。本站为非官方项目，与 Ethereum Foundation、Bitcoin Core 无隶属关系。
